Module 3 — DAX & Filter Context

Reason about evaluation context first. The exam typically rewards understanding what filters exist and how a DAX expression changes them.

Concept 1

Filter context, row context, CALCULATE & context transition

  • Filter context comes from visuals, slicers, filters, relationships and DAX.
  • Row context means current row and exists naturally in calculated columns and iterators.
  • Measures already evaluate in filter context; CALCULATE is not required merely for slicer awareness.
  • CALCULATE evaluates an expression under modified filter context.
  • Inside row context, CALCULATE can perform context transition.
DAX
Blue Sales =
CALCULATE (
    [Total Sales],
    Product[Color] = "Blue"
)
  • [Total Sales] is the expression being evaluated.
  • CALCULATE modifies filter context.
  • The Product[Color] filter becomes Blue while unrelated filters can remain.
Exam gotcha: A base measure like SUM(Sales[Amount]) already responds to a Region slicer.
Concept 2

DAX filter modifiers

  • REMOVEFILTERS() explicitly removes selected filters.
  • ALL() can remove filters and can also return an unfiltered table expression.
  • ALLEXCEPT(Table, Col...) removes filters from a table except listed columns.
  • KEEPFILTERS() intersects a new CALCULATE filter with an existing same-column filter.
  • Same-column Boolean filters in CALCULATE normally replace the existing filter unless KEEPFILTERS is used.
DAX
Category % =
DIVIDE (
    [Total Sales],
    CALCULATE (
        [Total Sales],
        REMOVEFILTERS ( Product[Category] )
    )
)
  • The numerator uses the current category.
  • The denominator removes only the Product[Category] filter.
  • Date, Region and other unrelated filters remain.
  • DIVIDE safely handles a zero/blank denominator.
Exam gotcha: REMOVEFILTERS(Product[Category]) does not remove Date, Region or unrelated dimension filters.
Concept 3

Iterators, FILTER, VALUES & aggregation choices

  • SUMX, AVERAGEX, MINX, MAXX iterate a table row by row.
  • Use SUM when summing an existing column; use SUMX when calculating an expression per row first.
  • FILTER() returns a filtered table expression.
  • VALUES(Column) returns distinct values visible in current filter context.
  • AVERAGEX(VALUES(Customer[ID]), [Total Sales]) averages customer totals, not transaction values.
DAX
Average Customer Sales =
AVERAGEX (
    VALUES ( Customer[CustomerID] ),
    [Total Sales]
)
  • VALUES returns distinct visible customers.
  • AVERAGEX iterates those customers.
  • [Total Sales] is evaluated for each customer.
  • The resulting customer totals are averaged.
Exam gotcha: AVERAGE(Sales[Amount]) and average sales per customer are different questions.
Concept 4

Variables & safe arithmetic

  • Use VAR for readable intermediate results and to avoid repeating expressions.
  • A scalar variable stores the result evaluated where it is defined.
  • Referencing a stored scalar inside a later CALCULATE does not automatically re-evaluate the variable in the new context.
  • Use DIVIDE() for safe division when the denominator can be zero/blank.
  • Use RETURN after variable declarations.
DAX
YoY Growth % =
VAR CurrentSales = [Total Sales]
VAR PriorSales = [Prior Year Sales]
RETURN
    DIVIDE ( CurrentSales - PriorSales, PriorSales )
  • VAR stores intermediate scalar results.
  • RETURN defines the final output expression.
  • The growth denominator is PriorSales.
Exam gotcha: Do not assume variables behave like formulas that are recomputed every time their name is referenced.
Concept 5

Date intelligence & period comparisons

  • SAMEPERIODLASTYEAR shifts the current date set one year back.
  • DATEADD shifts dates by a selected interval such as month or year.
  • TOTALYTD evaluates a measure over year-to-date dates.
  • YoY Growth is typically (Current - Prior) / Prior.
  • Sound date-table design and date context are prerequisites for reliable time intelligence.
DAX
Prior Year Sales =
CALCULATE (
    [Total Sales],
    SAMEPERIODLASTYEAR ( 'Date'[Date] )
)
  • SAMEPERIODLASTYEAR returns the corresponding prior-year date set.
  • CALCULATE reevaluates [Total Sales] under that shifted date context.
Exam gotcha: For YoY growth, the prior-year value is the normal comparison baseline/denominator.
Concept 6

Semi-additive measures, calculation groups & DAX queries

  • Balances and inventory snapshots are often additive across entities but not across time.
  • A closing-balance measure should use the latest applicable data snapshot, not sum all daily snapshots.
  • Calculation groups reduce measure proliferation for recurring transformations such as Current, YTD, PY and YoY.
  • SELECTEDMEASURE() refers to the measure transformed by a calculation item.
  • In DAX query view, EVALUATE returns a table expression.
DAX
// Example calculation item
CALCULATE (
    SELECTEDMEASURE(),
    DATESYTD ( 'Date'[Date] )
)

// DAX query example
EVALUATE
SUMMARIZECOLUMNS (
    Product[Category],
    "Sales", [Total Sales]
)
  • SELECTEDMEASURE refers to whichever measure a calculation group is transforming.
  • DATESYTD applies a year-to-date date set.
  • EVALUATE is a DAX query keyword that returns a table expression.
  • SUMMARIZECOLUMNS groups model results for inspection.
Exam gotcha: A calculation group is useful when many measures need the same transformations; it can be unnecessary for one isolated measure.
