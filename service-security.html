Module 5 — Power BI Service & Security

Separate collaboration, distribution, permissions, data security and refresh. Least privilege is a recurring Microsoft-style best answer.

Concept 1

Workspaces, roles, apps & distribution

  • Workspace roles: Admin, Member, Contributor, Viewer.
  • Use least privilege. Viewer is the normal consumption role where RLS should apply.
  • Workspace = collaboration/authoring; App = curated consumer distribution.
  • App audiences can show different content subsets to different groups.
  • Direct sharing/item-level access can suit a small targeted audience.
Exam gotcha: Do not make a user Contributor merely because they need Build permission on a semantic model.
Concept 2

Dashboards & tiles

  • A Power BI dashboard is a single-page canvas in the Power BI service.
  • A tile is a snapshot/item pinned to a dashboard from a report, Q&A or other supported source.
  • Standalone tiles can include text, images, video, streaming data and web content.
  • Dashboards are Service features; they are not Power BI Desktop report pages.
  • A pinned tile can retain the originally pinned visualization type even if the report visual type later changes, while data can continue to refresh.
Exam gotcha: Dashboard ≠ report. Dashboard is one Service page of tiles; reports can be multi-page and highly interactive.
Concept 3

Subscriptions & data alerts

  • Subscriptions deliver report/dashboard content on a schedule and supported conditions.
  • Classic data alerts notify a user when supported dashboard metric tiles cross thresholds.
  • Classic alerts apply to supported card, KPI and gauge dashboard tiles and depend on refreshed data.
  • Alerts are personal to the creator.
  • Know the distinction: scheduled delivery vs metric threshold notification.
Exam gotcha: A Monday morning email is a subscription. 'Notify me when KPI < 90' is a data alert.
Concept 4

Gateway, scheduled refresh & automatic page refresh

  • An on-premises data gateway provides Power BI Service connectivity to supported on-prem sources.
  • Standard mode is designed for shared/enterprise use; personal mode is limited/individual.
  • Scheduled refresh updates imported semantic-model data.
  • Automatic page refresh periodically re-queries supported report-page visuals, commonly in DirectQuery monitoring scenarios.
  • Troubleshoot refresh from refresh history/error details, then connectivity, credentials/permissions and source/model changes.
Exam gotcha: Gateway online does not guarantee valid source credentials. Scheduled refresh and automatic page refresh solve different problems.
Concept 5

Semantic-model permissions & row-level security

  • Read = consume; Build = create new reports/analysis from a semantic model; Reshare = grant access onward.
  • Viewer + Build is a common least-privilege combination when a user must be RLS-restricted but create reports.
  • Dynamic RLS often uses a mapping table with USERPRINCIPALNAME().
  • Assign users/groups to roles after publishing.
  • Multiple RLS roles are additive (union), not an intersection.
DAX
UserAccess[UPN] = USERPRINCIPALNAME()
  • USERPRINCIPALNAME returns the signed-in user's principal name in the Service.
  • The RLS role keeps mapping-table rows for that user.
  • Relationships should then propagate the allowed access to business data.
Exam gotcha: Two restrictive RLS roles usually broaden a user's visible rows rather than making them more restrictive.
Concept 6

OLS, sensitivity, endorsement, lineage, publish & update

  • OLS restricts model objects such as tables/columns; RLS restricts rows; hiding a field is not security.
  • Sensitivity labels classify/protect content under organizational policy.
  • Promoted = recommended; Certified = stronger formal organizational validation.
  • Lineage/impact analysis shows dependencies; Usage metrics show adoption; Performance Analyzer shows report execution timings.
  • Publish deploys report/model definition changes; refresh updates imported data. Apps may need to be updated after workspace changes.
Exam gotcha: Refresh cannot deploy a new report page or measure. Usage metrics cannot diagnose why a visual is slow.
