Module 1 — Prepare the Data

Choose the right storage/connection approach, shape and validate data efficiently, preserve folding, and understand how parameters and refresh policies affect loading.

Concept 1

Storage modes & connections

  • Import stores a copy in the semantic model and normally gives the fastest interaction; refresh is required for source changes.
  • DirectQuery leaves data at the source and report interactions can issue source queries.
  • DirectLake is a Fabric/OneLake storage mode and is distinct from DirectQuery.
  • Know when to connect to a shared semantic model to reuse governed measures and relationships.
  • Credentials authenticate to a source; an on-premises gateway provides connectivity. These are separate concerns.
Exam gotcha: Do not choose DirectQuery merely because a table is large. Freshness, platform, source capability and performance all matter.
Concept 2

Data profiling, quality, errors & types

  • Use column quality, distribution and profile statistics to inspect valid/error/empty values, distinctness and distributions.
  • Power Query profiling may use the top 1,000 rows; switch to the entire dataset before concluding a key is unique.
  • Remove Errors drops rows; Replace Errors preserves rows and substitutes a value.
  • Use Change Type using Locale for ambiguous dates/numbers.
  • IDs and postal codes can be numeric-looking but often belong as text.
Exam gotcha: Distinct count and unique-value count are different profiling ideas, and a sample of 1,000 rows is not proof of uniqueness for the full table.
Concept 3

Core transformations & Power Query M

  • Know Split, Extract, Replace Values, Fill Down/Up, Group By, Transpose, Promote/Demote Headers, Conditional Column, Custom Column and Index.
  • In M, each commonly represents a row function.
  • Pivot turns row values into columns; Unpivot turns columns into attribute/value rows.
  • Unpivot Other Columns is resilient when new month/year columns may appear.
  • Convert nested JSON/XML/list/record structures into a tabular shape before modeling.
Power Query M
Table.AddColumn(
    Sales,
    "Revenue",
    each [Quantity] * [UnitPrice],
    type number
)
  • Table.AddColumn returns the input table plus a new column.
  • "Revenue" is the new column name.
  • each evaluates the row expression for every row.
  • type number assigns the result data type.
Exam gotcha: Transpose is not Pivot. Also, an unnecessary Index step can add work and may interrupt query folding.
Concept 4

Merge, append, joins & folder combinations

  • Append stacks rows; Merge joins columns by matching keys.
  • Left Anti returns rows from the left table with no match; Right Anti does the reverse; Full Outer keeps all rows from both sides.
  • Join columns should use compatible data types and equivalent business keys.
  • For recurring same-schema files, use a Folder connector + Combine Files rather than manually importing each file.
  • Merge is a Power Query transformation; model relationships serve a different purpose after load.
Exam gotcha: Append and Merge are frequent distractors. Ask whether the requirement is 'more rows' or 'more columns by key.'
Concept 5

Query folding & efficient shaping

  • Query folding pushes supported Power Query operations back to the source.
  • Filter rows and remove unnecessary columns early when logically possible and foldable.
  • A non-foldable step can prevent later steps from folding.
  • Use native/folding indicators or View Native Query where supported.
  • Folding is valuable for Import refresh too; it is not only a DirectQuery concept.
Power Query M
let
    Source = Sql.Database("SERVER", "SalesDB"),
    Sales = Source{[Schema="dbo", Item="Sales"]}[Data],
    Filtered = Table.SelectRows(Sales, each [OrderDate] >= #date(2026,1,1)),
    Selected = Table.SelectColumns(Filtered,{"OrderDate","ProductKey","Amount"})
in
    Selected
  • Source connects to SQL Server.
  • Filtered restricts rows before later transformations.
  • Selected keeps only required columns.
  • When supported, these operations can fold to SQL.
Exam gotcha: Do not assume Power Query automatically optimizes every step sequence or that Import mode makes folding irrelevant.
Concept 6

Parameters, incremental refresh & load settings

  • Power Query parameters can make server names, paths, dates and transformation inputs reusable.
  • For incremental refresh, create Date/Time RangeStart and RangeEnd parameters and filter with >= RangeStart and < RangeEnd.
  • The store/archive period is larger history retained; the refresh period is the recent subset refreshed.
  • Detect data changes can use a modification timestamp such as LastModifiedDate.
  • Turn Enable load off for staging queries that should not become model tables; Include in report refresh is a separate setting.
Power Query M
Table.SelectRows(
    Source,
    each [TransactionDate] >= RangeStart
        and [TransactionDate] < RangeEnd
)
  • RangeStart and RangeEnd are Date/Time parameters.
  • >= on the start and < on the end create adjacent non-overlapping boundaries.
  • The filter should fold when the source supports it.
Exam gotcha: The business transaction date normally defines partitions, while a modification date can tell Power BI whether data changed.
