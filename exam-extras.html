Module 6 — High-Value Exam Extras

Experienced analysts often miss features they do not use every day. This module revisits paginated reports, tiles, AI visuals, DirectLake, calculation groups, DAX query view, visual calculations and advanced analytics.

Concept 1

Paginated reports & visual calculations

  • Paginated reports are optimized for printing, PDF, exact layout and long tables that span pages.
  • They are authored with Power BI Report Builder and use RDL technology.
  • Standard Power BI reports are optimized for interactive exploration.
  • Visual calculations operate on data in a visual and are useful for visual-local calculations.
  • Reusable governed logic should usually remain in model measures or calculation groups.
Exam gotcha: Many rows alone does not automatically mean paginated. Look for pixel-perfect printing, page control, repeating headers and complete multi-page output.
Concept 2

Dashboards & tiles

  • A Power BI dashboard is a single-page canvas in the Power BI service.
  • A tile is a snapshot/item pinned to a dashboard from a report, Q&A or other supported source.
  • Standalone tiles can include text, images, video, streaming data and web content.
  • Dashboards are Service features; they are not Power BI Desktop report pages.
  • A pinned tile can retain the originally pinned visualization type even if the report visual type later changes, while data can continue to refresh.
Exam gotcha: Dashboard ≠ report. Dashboard is one Service page of tiles; reports can be multi-page and highly interactive.
Concept 3

AI visuals, Q&A, narrative & Copilot

  • Key influencers ranks factors that drive an outcome.
  • Decomposition tree breaks a measure across dimensions and supports AI high/low splits.
  • Q&A answers user natural-language questions with visuals.
  • Narrative features generate textual summaries of insights.
  • The current exam scope includes Copilot-assisted report page creation/suggestions and Copilot semantic-model/narrative summarization.
Exam gotcha: Key influencers asks 'what drives the outcome?'; decomposition tree asks 'how can I break this measure down?' Q&A is user-prompted natural language.
Concept 4

Semi-additive measures, calculation groups & DAX queries

  • Balances and inventory snapshots are often additive across entities but not across time.
  • A closing-balance measure should use the latest applicable data snapshot, not sum all daily snapshots.
  • Calculation groups reduce measure proliferation for recurring transformations such as Current, YTD, PY and YoY.
  • SELECTEDMEASURE() refers to the measure transformed by a calculation item.
  • In DAX query view, EVALUATE returns a table expression.
DAX
// Example calculation item
CALCULATE (
    SELECTEDMEASURE(),
    DATESYTD ( 'Date'[Date] )
)

// DAX query example
EVALUATE
SUMMARIZECOLUMNS (
    Product[Category],
    "Sales", [Total Sales]
)
  • SELECTEDMEASURE refers to whichever measure a calculation group is transforming.
  • DATESYTD applies a year-to-date date set.
  • EVALUATE is a DAX query keyword that returns a table expression.
  • SUMMARIZECOLUMNS groups model results for inspection.
Exam gotcha: A calculation group is useful when many measures need the same transformations; it can be unnecessary for one isolated measure.
Concept 5

Model properties & performance optimization

  • Remove unused rows/columns, especially high-cardinality long text.
  • Reduce unnecessary granularity and precision when requirements allow.
  • Set useful names, formats, data categories and default summarization.
  • Numeric identifiers often should use Don't summarize; postal/geographic fields should use appropriate data categories.
  • Performance Analyzer identifies slow report visuals; DAX query view lets you author/run DAX queries against the model.
Exam gotcha: Hiding a column improves the field list but does not reduce VertiPaq storage and is not security.
Concept 6

Storage modes & connections

  • Import stores a copy in the semantic model and normally gives the fastest interaction; refresh is required for source changes.
  • DirectQuery leaves data at the source and report interactions can issue source queries.
  • DirectLake is a Fabric/OneLake storage mode and is distinct from DirectQuery.
  • Know when to connect to a shared semantic model to reuse governed measures and relationships.
  • Credentials authenticate to a source; an on-premises gateway provides connectivity. These are separate concerns.
Exam gotcha: Do not choose DirectQuery merely because a table is large. Freshness, platform, source capability and performance all matter.
Concept 7

Analyze features, reference lines, error bars, forecasting, anomalies & clustering

  • Constant/reference lines show fixed goals; average lines show computed averages.
  • Forecasting estimates future points from a historical time series.
  • Error bars communicate uncertainty or variation around values.
  • Anomaly detection identifies unexpected spikes/dips in supported line-chart scenarios.
  • Grouping combines known discrete categories; binning creates ranges; clustering discovers natural groups.
Exam gotcha: Forecast = future estimates; anomaly detection = unusual historical points; error bars = uncertainty.
