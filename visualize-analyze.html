Module 4 — Visualize & Analyze Data

Choose the feature that directly fits the analytical goal while keeping reports accessible, usable and maintainable.

Concept 1

Choosing & configuring visuals

  • Line = trend over time; bar/column = category comparison; scatter = relationship between numeric variables.
  • Card = single value; KPI = actual/target/trend; Gauge = progress toward goal/range.
  • Table = flat detail; Matrix = hierarchical/cross-tab with expand/collapse.
  • Maps require meaningful geographic fields and appropriate data categories.
  • Choose the simplest visual that communicates the analytical question clearly.
Exam gotcha: A pie/donut is not the automatic answer for part-to-whole when many categories make comparison difficult.
Concept 2

Filters, slicers, Top N & interactions

  • Filters can be visual-, page- or report-level.
  • Top N needs a ranking value/measure; sorting descending alone does not restrict to N categories.
  • Edit interactions can set Filter, Highlight or None.
  • Filter restricts target data; Highlight retains broader context and emphasizes a subset.
  • Sync slicers applies the same slicer selection across pages and can keep synchronized slicers hidden on some pages.
Exam gotcha: Sort order is not a Top N filter.
Concept 3

Bookmarks, Selection pane, tooltips & drillthrough

  • Bookmarks can capture Data, Display and Current page state.
  • Use the Selection pane for visibility/layer order.
  • For show/hide panels without resetting slicers, avoid capturing Data in the bookmark.
  • Report page tooltips show rich hover context; drillthrough navigates to a filtered detail page.
  • Drill down moves deeper through hierarchy levels inside the same visual.
Exam gotcha: Tooltip = hover without navigation. Drillthrough = navigate with context. Drill down = hierarchy within the same visual.
Concept 4

Themes, conditional formatting, accessibility, mobile & personalization

  • Themes provide consistent report styling and can be customized with JSON.
  • Conditional formatting can use rules, color scales, field values, icons and data bars.
  • Accessibility: meaningful alt text, logical tab order, sufficient contrast and don't rely on color alone.
  • Use Mobile layout for phone-specific visual arrangement.
  • Personalize visuals lets consumers modify their own visual exploration without editing the published report.
Exam gotcha: Hiding data behind color alone is an accessibility failure. Export also does not bypass RLS.
Concept 5

Analyze features, reference lines, error bars, forecasting, anomalies & clustering

  • Constant/reference lines show fixed goals; average lines show computed averages.
  • Forecasting estimates future points from a historical time series.
  • Error bars communicate uncertainty or variation around values.
  • Anomaly detection identifies unexpected spikes/dips in supported line-chart scenarios.
  • Grouping combines known discrete categories; binning creates ranges; clustering discovers natural groups.
Exam gotcha: Forecast = future estimates; anomaly detection = unusual historical points; error bars = uncertainty.
Concept 6

AI visuals, Q&A, narrative & Copilot

  • Key influencers ranks factors that drive an outcome.
  • Decomposition tree breaks a measure across dimensions and supports AI high/low splits.
  • Q&A answers user natural-language questions with visuals.
  • Narrative features generate textual summaries of insights.
  • The current exam scope includes Copilot-assisted report page creation/suggestions and Copilot semantic-model/narrative summarization.
Exam gotcha: Key influencers asks 'what drives the outcome?'; decomposition tree asks 'how can I break this measure down?' Q&A is user-prompted natural language.
Concept 7

Paginated reports & visual calculations

  • Paginated reports are optimized for printing, PDF, exact layout and long tables that span pages.
  • They are authored with Power BI Report Builder and use RDL technology.
  • Standard Power BI reports are optimized for interactive exploration.
  • Visual calculations operate on data in a visual and are useful for visual-local calculations.
  • Reusable governed logic should usually remain in model measures or calculation groups.
Exam gotcha: Many rows alone does not automatically mean paginated. Look for pixel-perfect printing, page control, repeating headers and complete multi-page output.
